Рекомендации:

1. Выбор моделей (минимум 5, покрыть все парадигмы)
  * Обязательно включить DummyClassifier (baseline).
  * Выбрать 1 линейную: LogisticRegression или SVM (линейное ядро).
  * Выбрать 1 простую деревянную: DecisionTree или KNN.

2. Метрики: accuracy не использовать для выбора
* Главная метрика — PR-AUC (average_precision). Именно по ней выбирать лучшую модель.
- Вторичная — ROC-AUC.
- Для отчёта — Precision, Recall, F1.
* Accuracy печатать только для демонстрации его бесполезности при дисбалансе.
3. Сравнение моделей: только через кросс-валидацию
* Использовать StratifiedKFold(5) — сохраняет пропорцию классов в каждом фолде.
* Считать среднее и стандартное отклонение PR-AUC по фолдам.
* Проверить статистическую значимость разницы между топ-моделями (paired t-test по фолдам).
* Если разница незначима — выбрать более простую модель.
4. Подбор гиперпараметров: не GridSearch
* GridSearchCV запрещён: проклятие размерности, дискретность, равнозначный перебор плохих и хороших комбинаций.
* Использовать Optuna (Bayesian Optimization): адаптивный поиск, непрерывные пространства, встроенное прунинг (отсечение безнадёжных комбинаций). Альтернатива гиперопт
* Количество trials: 20–30 для линейных, 50–100 для бустингов.
* Для бустингов обязательно early stopping на validation set внутри CV.
5. Работа с дисбалансом
* Всегда включать веса классов: class_weight="balanced", scale_pos_weight, auto_class_weights="Balanced".
* Пороговая корректировка: после обучения подбирать threshold не 0.5, а оптимальный для F1 или F2 на validation set.
- SMOTE/ADASYN — только если recall низкий даже с весами; обязательно внутри Pipeline (иначе leakage).

* Разделение: train / validation / test (например, 60/20/20) или CV с отдельным hold-out test.

* Для бустингов: графики обучения (train vs validation metric по итерациям) + early stopping.
* Для всех моделей: learning curves (зависимость train/val score от размера выборки). Большой gap = переобучение.
* Validation curves: зависимость метрики от одного параметра (например, n_estimators). Плато/падение val = точка переобучения.
7. Финальная структура отчёта
* Таблица: модель × PR-AUC(CV) × ROC-AUC × Precision × Recall × F1 × F2.
* Графики:

  * ROC-кривые, 
  * confusion matrix лучшей модели,

## Апісанне датасэта

`online_shoppers_intention.csv` - [12330x18] змяшчае інфармацыю пра 12 330 сесій на сайце інтэрнэт-крамы. Кожны радок апісвае паводзіны асобнага карыстальніка за адну сесію на працягу года.  

**Асноўныя характарыстыкі**  
 * Аб’ём: 12 330 сесій (назіранняў).  
 * Атрыбуты: 18 прыкмет (**10 лічбавых** і **8 катэгарыяльных**).  
 * Мэтавая зменная **"Revenue"**: бінарны паказчык (True/False), які паказвае, ці здзейсніў карыстальнік пакупку. 
 Каля 84,5% сесій завяршыліся без пакупкі, а 15,5% — з пакупкай.  
 * Пропускаў у дадзеных няма.   

### 1. Метрыкі старонак (Page-view Metrics)

Фарміруюцца на аснове URL-адрасоў старонак, наведаных карыстальнікам, і абнаўляюцца ў рэжыме рэальнага часу падчас дзеянняў карыстальніка (напрыклад, пераходу з адной старонкі на іншую): 

* **"Administrative"** — колькасць наведаных старонак адміністрацыйнага тыпу (кіраванне акаўнтам і г.д.).
* **"Administrative Duration"** — агульны час, праведзены на адміністрацыйных старонках.
* **"Informational"** — колькасць наведаных інфармацыйных старонак (пра кампанію, кантакты).
* **"Informational Duration"** — агульны час, праведзены на інфармацыйных старонках.
* **"Product Related"** — колькасць наведаных старонак, звязаных з таварамі.
* **"Product Related Duration"** — агульны час, праведзены на старонках тавараў.

### 2. Метрыкі Google Analytics

Прадстаўляюць паказчыкі, якія вымяраюцца сістэмай Google Analytics для кожнай старонкі сайта электроннай камерцыі: 

* **"Bounce Rate"** — адсотак наведвальнікаў, якія заходзяць на сайт з гэтай старонкі, а затым пакідаюць яго ("адскокваюць") без стварэння іншых запытаў да сервера аналітыкі падчас сесіі.
* **"Exit Rate"** — адсотак праглядаў гэтай старонкі, якія сталі апошнімі ў сесіі (вылічваецца адносна ўсіх праглядаў гэтай старонкі).
* **"Page Value"** — сярэдняя каштоўнасць вэб-старонкі, якую карыстальнік наведаў перад завяршэннем транзакцыі.

### 3. Кантэкстныя і часавыя прыкметы

* **"Special Day"** — блізкасць часу наведвання сайта да пэўнага асаблівага дня (напрыклад, Дня маці, Дня святога Валянціна), калі сесіі з большай верагоднасцю завяршаюцца купляй. Значэнне вызначаецца з улікам дынамікі e-commerce (час паміж замовай і дастаўкай). 
  * *Прыклад:* для Дня святога Валянціна значэнне будзе ненулявым (ад 0 да 1) у перыяд з 2 па 12 лютага, роўным 0 да і пасля гэтых дат, і дасягне максімуму (1) менавіта 8 лютага.
* **Выходныя і месяцы** — лагічнае значэнне (Boolean), ці прыпадае візіт на выходны дзень, а таксама месяц года.

### 4. Профіль карыстальніка і трафік

Датасэт таксама ўключае тэхнічныя і дэмаграфічныя характарыстыкі сесіі: 

* Аперацыйная сістэма (**operating system**)
* Браўзер (**browser**)
* Рэгіён (**region**)
* Тып трафіку (**traffic type**)
* Тып наведвальніка (**visitor type**): той, хто вярнуўся (returning), ці новы наведвальнік (new visitor).

```bash

```

### 2. Стварыць віртуальны асяродак

```bash
python3 -m venv .venv
```

На Windows, калі `python3` не знайшлі:

```bash
python -m venv .venv
```

### 3. Актываваць асяродак

**Windows (PowerShell):**

```powershell
.\.venv\Scripts\Activate.ps1
```

**Windows (cmd):**

```bat
.\.venv\Scripts\activate
```

**Linux / macOS (Apple):**

```bash
source .venv/bin/activate
```

```bash

python main.py
```
